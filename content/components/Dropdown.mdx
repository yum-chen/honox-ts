# Introduction

An interactive overlay component that displays a contextual list of actions, options, or sub-menus when triggered. It supports custom layout alignments, automatic viewport collision flipping, center-aligned pointer arrows, checkbox/radio state selections, cascading multi-level submenus, and mouse hover or click interaction modes.

The **Dropdown** component is fully integrated as a `menu` block in the **Page Builder**, enabling content authors and developers to easily construct custom navigation indices, profile option lists, or actions directly within the CMS.

***

# Usage via CMS Page Builder (JSON)

These examples illustrate how content editors bind and structure custom dropdown menus inside the JSON page schemas (`content/pages/*.json`).

## 1. Standard Settings Action Menu

A standard click-triggered action menu containing simple trigger options, visual divider separators, toggle checkboxes, and nested choices.

<DemoPreview>
  <Dropdown
    trigger={<Button>Open Actions</Button>}
    items={[
      { type: "item", label: "Edit Project Details", value: "edit" },
      { type: "item", label: "Duplicate Document", value: "duplicate" },
      { type: "separator" },
      { type: "checkbox", label: "Enable Notifications", value: "notify", checked: true },
    ]}
  />
</DemoPreview>

```json
{
  "type": "menu",
  "triggerText": "Open Actions",
  "items": [
    { "type": "item", "label": "Edit Project Details", "value": "edit" },
    { "type": "item", "label": "Duplicate Document", "value": "duplicate" },
    { "type": "separator" },
    { "type": "checkbox", "label": "Enable Notifications", "value": "notify", "checked": true }
  ]
}
```

Features an automatic mouse hover trigger with a center-aligned visual arrow pointer and a right-aligned boundary layout.

# CMS Configuration Reference

These fields map directly to Sveltia CMS block properties under `public/admin/config.yml` or the Page Builder configurations:

| Property | CMS Field Type | Default | Description / Supported Options |
| :--- | :--- | :--- | :--- |
| **Trigger Text** (`triggerText`) | `string` | `"Open Menu"` | Label displayed on the trigger button. |
| **Menu Items** (`items`) | `list` | - | Array of menu entries containing type, label, value, and checkbox bindings. |
| **Trigger Mode** (`triggerMode`) | `select` | `"click"` | Action mode required to activate the menu. <br/>• Options: `"click"`, `"hover"`. |
| **Placement** (`placement`) | `select` | `"bottom-start"` | Visual opening alignment of the menu relative to the trigger bounds. <br/>• Options: `"bottom-start"`, `"bottom-end"`, `"top-start"`, `"top-end"`, `"left-start"`, `"right-start"`. |
| **Show Arrow** (`arrow`) | `boolean` | `false` | Renders a small graphic pointing arrow from the menu card to the trigger button. |
| **Unmount Hidden** (`destroyOnHidden`) | `boolean` | `false` | Completely unmounts menu child elements from the DOM tree when collapsed. |
| **Force Interactive** (`interactive`) | `boolean` | `true` | Hydrates the dropdown components to trap focus and handle keyboard cycling. |

# Developer Notes & Accessibility

- **Hydration Island:** As a complex layout coordinating absolute viewport tracking, keyboard arrow hooks, focus trapping, and hover delay timers, the Dropdown component hydrates as an interactive client-side island by default (`"interactive": true`).
- **WAI-ARIA Compliance:** Under the hood, the trigger acts as a high-fidelity semantic trigger (`role="button"`, `aria-haspopup="menu"`, `aria-expanded`). Items utilize correct menu tags (`role="menu"`, `role="menuitem"`, `role="menuitemcheckbox"`). Users can cycle items seamlessly using keyboard arrow keys, jump to prefixes using typeahead printable characters, or close using `Escape`.
- **Form State Preservation:** Checkbox and radio items inside the Dropdown automatically preserve their active state bindings inside standard client-side state parameters (`checkedOverridesRef`), preventing hydration conflicts across render boundaries.
